Chapter 12

F·D·Q·Zfh: 부동소수점

RISC-V의 부동소수점은 새로 발명한 것이 아니다. IEEE 754-2008 표준을 그대로 따르고, 그 위에 레지스터 파일 f0–f31, 상태 레지스터 fcsr, 그리고 몇 가지 RISC-V다운 결정을 얹었다. 예외가 생겨도 트랩하지 않고 플래그만 세우며, NaN은 언제나 하나의 정해진 모양(정규 NaN)으로 만들고, 좁은 값을 넓은 레지스터에 넣을 때는 위쪽을 1로 채우는 NaN 박싱을 쓴다. 이 장에서는 비트 하나하나를 직접 눌러 보며 F·D·Q·Zfh와 BF16, Zfa, Zfinx까지 정리한다.

  • binary16·bfloat16·binary32·binary64·binary128의 부호·지수·가수 배치를 읽고 값과 FCLASS 분류를 계산한다.
  • f0–f31, FLEN, fcsr(frm 7:5, fflags 4:0)과 CSR 주소 0x001–0x003을 안다.
  • RNE·RTZ·RDN·RUP·RMM 다섯 반올림 모드와 rm = 111(DYN)의 뜻을 구별한다.
  • R4 형식의 FMA 네 명령, 부호 주입, 비교, 변환, FCLASS 명령을 정리한다.
  • NV·DZ·OF·UF·NX 플래그가 언제 서는지, 정규 NaN 0x7fc00000이 무엇인지 안다.
  • NaN 박싱 규칙과, 박싱이 깨진 값을 읽을 때 무슨 일이 일어나는지 설명한다.
  • Zfh/Zfhmin, BF16(Zfbfmin·Zvfbfmin·Zvfbfwma), Zfa, Zfinx/Zdinx/Zhinx의 역할을 비교한다.
F v2.2 D v2.2 Q v2.2 Zfh v1.0 BF16 v1.0 Zfa v1.0 Zfinx v1.0

IEEE 754 형식: 부호, 지수, 가수

IEEE 754 이진 부동소수점 수는 세 부분으로 이루어진다. 부호 1비트, 치우침(bias)을 더해 저장하는 지수, 그리고 맨 앞의 1을 생략하고 저장하는 가수(fraction)다. 정규수의 값은 (−1)^s × 1.f × 2^(E − bias)다. 지수 비트가 모두 0이면 0 또는 비정규수(subnormal), 모두 1이면 무한대 또는 NaN이다. RISC-V의 다섯 가지 형식은 이 틀의 폭만 다르다.

f 레지스터와 fcsr

F 확장은 32개의 부동소수점 레지스터 f0–f31을 더한다. 정수 레지스터와 달리 f0도 평범한 레지스터다(늘 0이 아니다). 레지스터 폭을 FLEN이라 부르는데, F만 있으면 32, D가 있으면 64, Q가 있으면 128이다. 정수와 부동소수점 레지스터를 따로 둔 이유를 규격은 이렇게 설명한다. 같은 명령 폭으로 더 많은 레지스터를 쓸 수 있고, 슈퍼스칼라에서 레지스터 포트를 나눠 달기 쉽고, 부동소수점 유닛을 분리해 설계하거나 내부 재부호화(recoding)를 쓰기 쉽다. F 확장은 CSR 접근을 위해 Zicsr에 의존한다.

예외는 트랩이 아니라 플래그로, NaN은 정규 NaN으로

IEEE 754는 예외 상황(0으로 나누기 등)에서 트랩할지 기본값을 돌려줄지를 구현에 맡긴다. RISC-V는 트랩하지 않는다. 표준이 정한 기본 결과(무한대, NaN 등)를 돌려주고 fflags의 해당 비트만 세운다. 플래그를 직접 보고 분기하는 명령도 일부러 넣지 않았다. 필요하면 소프트웨어가 frflags로 읽어 확인한다.

FMIN/FMAX는 v2.2에서 바뀌었다

F v2.2부터 FMIN.S·FMAX.S는 IEEE 754-2008의 minNum/maxNum이 아니라 당시 제안된 754-201x의 minimumNumber/maximumNumber를 따른다. 둘은 신호 NaN 처리에서 다르다. 지금 규칙은 “NaN이 하나면 다른 쪽 값, 둘 다 NaN이면 정규 NaN, sNaN 입력은 결과가 NaN이 아니어도 NV”다. NaN이 하나라도 있으면 NaN을 내는 IEEE 754-2019 minimum/maximum은 Zfa의 FMINM/FMAXM이 제공한다.

D 확장과 NaN 박싱

D 확장은 f 레지스터를 64비트(FLEN = 64)로 넓히고 배정도 명령을 더한다. 이제 한 레지스터에 단정도 값과 배정도 값이 모두 들어갈 수 있다. 그렇다면 32비트 값을 64비트 레지스터에 넣을 때 위쪽 32비트는 무엇으로 채울까? RISC-V의 답은 NaN 박싱(NaN-boxing)이다. 위쪽 비트를 모두 1로 채운다.

  • 전송 명령(FLn/FSn, FMV.n.X/FMV.X.n): n비트 값을 f 레지스터로 들일 때는 올바르게 박싱한다. 내보낼 때는 아래 n비트만 쓰고 위쪽은 무시한다.
  • 그 밖의 모든 n비트 연산: 입력의 위쪽 FLEN−n비트가 모두 1인지 검사한다. 맞으면 아래 n비트를 값으로 쓰고, 아니면 입력을 n비트 정규 NaN으로 취급한다.
  • n비트 결과를 f 레지스터에 쓰는 연산은 반드시 위쪽을 모두 1로 채운다.
규격 원문에서
“The upper bits of a valid NaN-boxed value must be all 1s. Valid NaN-boxed n-bit values therefore appear as negative quiet NaNs (qNaNs) when viewed as any wider m-bit value, n < m ≤ FLEN.”

"D" Extension, NaN Boxing of Narrower Values — 예전 규격은 이 경우를 정하지 않았다. 지금 규칙은 구현마다 다른 동작을 없애면서도, 값을 내부 형식으로 재부호화하는 구현과 그렇지 않은 구현을 모두 수용한다.

Q, Zfh/Zfhmin, 그리고 BF16

Q(v2.2)는 128비트 4배 정도를 더한다(FLEN = 128, D에 의존). 새 load/store flq/fsq는 width 100을 쓰고, RV32·RV64 어디에도 fmv.x.q/fmv.q.x는 없어서 정수 레지스터로 옮기려면 메모리를 거친다. Zfh(v1.0)는 16비트 반정도 연산 전부를, Zfhmin은 그중 저장과 변환만(flh, fsh, fmv.x.h, fmv.h.x, fcvt.s.h, fcvt.h.s, D가 있으면 fcvt.d.h, fcvt.h.d, Q가 있으면 fcvt.q.h, fcvt.h.q) 담는다. 둘 다 F에 의존한다. Zfhmin 소프트웨어는 반정도를 “저장 형식”으로만 쓰고 계산은 단정도로 하는 경우를 겨냥한다.

BF16(v1.0) 규격은 세 확장으로 나뉜다. 모두 F에 의존하며, 이 규격의 BF16 명령은 비정규수를 완전히 지원한다.

BF16 값도 f 레지스터에서는 반정도와 똑같이 NaN 박싱된다. 변환은 BF16 ↔ FP32만 제공한다. 규격은 이 확장들이 “BF16을 FP32의 정밀도를 줄인 형태로 쓰는” 용도를 겨냥한다고 밝히며, 다른 형식과의 변환은 FP32를 거쳐 흉내 낼 수 있다고 설명한다. 벡터 쪽 이야기는 15장에서 이어진다.

Zfa: 자주 쓰는 연산을 한 명령으로

Zfa(v1.0)는 F에 의존하며, 라이브러리와 컴파일러가 여러 명령으로 흉내 내던 연산을 더한다. 가장 눈에 띄는 것은 fli(load immediate)다. 상수 하나를 쓰려고 메모리에서 읽거나 정수 레지스터를 거칠 필요 없이, rs1 필드의 5비트로 32개 상수 중 하나를 고른다.

Zfinx: f 레지스터 없는 부동소수점

작은 마이크로컨트롤러에게 32개짜리 레지스터 파일을 하나 더 두는 것은 큰 비용이다. Zfinx(v1.0, “z-f-in-x”)는 F의 연산 명령을 그대로 두되, f 레지스터를 읽고 쓰던 자리에서 같은 번호의 x 레지스터를 쓴다. f 레지스터가 없으니 전송 명령 flw, fsw, fmv.w.x, fmv.x.w, c.flw[sp], c.fsw[sp]는 빠진다. 메모리와는 정수 load/store로, 레지스터 사이는 정수 연산이나 부호 주입 명령으로 옮긴다. 문맥 교환 비용도 줄어든다.

핵심 정리

  1. RISC-V 부동소수점은 IEEE 754-2008을 따른다. F(v2.2)는 f0–f31(FLEN = 32)과 fcsr을, D·Q(v2.2)는 FLEN을 64·128로 넓힌다. fmt 필드는 S 00, D 01, H 10, Q 11.
  2. fcsr = frm[7:5] + fflags[4:0](NV DZ OF UF NX). CSR 주소는 fflags 0x001, frm 0x002, fcsr 0x003.
  3. rm: RNE 000, RTZ 001, RDN 010, RUP 011, RMM 100, 101·110 예약, 111 DYN(frm 사용).
  4. FMA 네 명령은 rs3를 가진 R4 형식을 쓰고 반올림을 한 번만 한다. 비교·분류·정수 변환은 결과를 정수 레지스터에 쓴다. FCLASS는 10비트 중 한 비트를 세운다.
  5. 예외는 트랩하지 않고 누적 플래그만 세운다. NaN 결과는 늘 정규 NaN(binary32: 0x7fc00000)이며 페이로드를 전파하지 않는다. tininess는 반올림 뒤에 판단한다.
  6. NaN 박싱: 좁은 값을 넣을 때 위쪽을 모두 1로 채우고, 좁은 연산은 박싱이 깨진 입력을 정규 NaN으로 취급한다.
  7. Zfh/Zfhmin은 반정도, BF16(Zfbfmin·Zvfbfmin·Zvfbfwma)은 bfloat16 변환과 벡터 누적, Zfa는 fli·fminm·fround·fcvtmod·fleq 등, Zfinx/Zdinx/Zhinx는 f 레지스터 없이 x 레지스터에서 부동소수점을 계산한다.

확인 퀴즈

fcsr의 frm 필드 위치와 frm CSR의 주소로 옳은 것은?

frm은 fcsr[7:5]이고 따로 0x002로 접근한다. fflags는 [4:0]·0x001, fcsr 전체는 0x003이다.

단정도 정규 NaN의 비트 패턴은?

부호 0, 지수 모두 1, 가수는 최상위(quiet) 비트만 1이다. 0x7f800000은 +∞다.

RV64D 하트에서 flw f1로 1.0f(0x3f800000)를 읽은 뒤 f1의 64비트 값은?

좁은 값을 f 레지스터에 넣는 전송 명령은 위쪽을 모두 1로 채운다(NaN 박싱).

16777217을 binary32로 변환할 때 RNE와 RMM의 결과로 옳은 것은?

정확히 중간이므로 RNE는 가수가 짝수인 16777216, RMM은 크기가 큰 16777218을 고른다.

RISC-V에서 1.0 / 0.0을 실행하면?

RISC-V는 부동소수점 예외로 트랩하지 않는다. IEEE 기본 결과 +∞와 함께 DZ 플래그만 선다.

FMADD.S가 FMUL.S + FADD.S 두 명령과 다른 점은?

FMA는 정확한 곱에 rs3를 더한 뒤 한 번만 반올림한다. 그래서 R4 형식(rs3 필드)이 필요하다.

feq.s와 flt.s에 같은 조용한 NaN을 넣었을 때 NV 플래그는?

flt/fle는 IEEE의 signaling 비교라 NaN이면 NV를 세우고, feq는 quiet 비교라 sNaN일 때만 세운다. 결과는 둘 다 0이다.

Zfinx에 대한 설명으로 틀린 것은?

Zfinx는 NaN 박싱 대신 위쪽 비트를 부호 비트로 채운다(부호 확장). 같은 레지스터에 정수도 살기 때문이다.
